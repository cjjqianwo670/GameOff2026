### 2026-11-25 · 设计变更：紫怪索敌改成随机

作者原话：「先诱饵，再随机圣坛内黑格，清除所在行或者列的黑格，圣坛内全空就攻击人」。

### 2026-11-25 · 重做挥剑音效（「太电子、不像剑」）

作者反馈原来的挥剑声太电子。原来的写法是「`_tone(..., "noise")` 噪声下滑 + 2400Hz 三角波泛音」，
两个问题：`_tone` 的 noise 是**相位的函数**（本质仍带音高，听感像电流嗡嗡），三角波泛音是**纯音**（像蜂鸣）。

**改动**（只动 `sfx.py` 的 `sword`，其它音效未碰）：

- 新增 `_white_noise(n, seed)`：固定种子真白噪，平谱、无音高。
- 新增 `_swept_band(x, cutoffs, q)`：Chamberlin 状态变量带通，截止频率逐采样点变化。
- 新增 `_sword_swing()`：三层合成
  1. 刃风：白噪过**先升后降**的带通（480 → 4180 → 480 Hz，峰在 31.5% 处），再并一条窄的高频带补「嘶」；
  2. 金属余振：740Hz × 非谐比 1 / 2.76 / 5.40 / 8.93，每个再叠一份 +0.6% 失谐副本产生拍频，指数衰减 50~200ms；
  3. 低频重量：105 → 52Hz 正弦，90ms。
  统一加 3ms 起音 + 50ms 淡出，去爆音。时长 0.16s → 0.26s。
- `_GAIN["sword"]` 0.34 → 0.46（噪声能量分散，按耳感补回来）。

**验证**：`_verify_act1_sfx.py` 143/143；全量 `_run_all.py` 1031/1031；`_smoke_full_run.py` FULL RUN OK。

### 2026-11-24 · 修复音效播放链路（单声道 PCM 被当成立体声）

用户反馈「游戏没有音效」。实际 14 个音效都在播，但格式错位了两层：`sfx.build()` 返回的是**带 44 字节 WAV 头的单声道** bytes，直接塞给 `Sound(buffer=...)` 会被当成**立体声裸 PCM** —— 头被当采样播出去、单声道数据被交错，时长腰斩（实测 paint 0.05s → 0.0252s，ui 0.025s → 0.012s）。原 `_verify_act1_sfx.py` 只验「字节非空 / 彼此不同 / 假 mixer 调了 play」，验不出真实播放格式。

- `sfx.py`：新增 `RATE`、`build_pcm(name)`（裸 PCM；`build()` 仍返回 WAV，留给测试/调试）、`to_channels(pcm, n)`（设备只给立体声时按声道补数据）。
- `game.py` `_Audio`：优先 `pygame.mixer.init(44100, -16, 1, 512, allowedchanges=0)`；设备拒绝单声道时退回 `AUDIO_ALLOW_CHANNELS_CHANGE`，再按 `get_init()[2]` 把 PCM 补成实际声道数；播放改用 `build_pcm`。
- 实测：mixer 从 `(44100,-16,2)` 变 `(44100,-16,1)`，14 个音效时长全部恢复标称值（paint 0.05 / ui 0.025 / clear 0.55）。

### 2026-11-11 晚 · 修「按回车会涂格子」

- 作者反馈：站在格子上按回车，脚下被涂黑。**不是错觉，是真串键。**
- 根因：`InputState.down()` 里那句兜底 —— `pygame.key.get_pressed()[sc]`。
传进去的是 **scancode**，而那个数组在部分环境下按 **keycode** 索引：
**Enter 的 keycode = 13，J 的 scancode = 13**，于是按回车 = 按 J = 涂格。
字母里只有 J 会撞（其余 scancode 在 keycode 空间对应 Ctrl 组合），所以只有回车出问题。
- 定位过程（值得记，因为这类 bug 靠读代码推理不出来）：
  1. 先确认 `e.scancode` 是对的（真实窗口 PostMessage 回读：Enter = `key=13, scancode=40`）；
  2. 再排掉 keycode 混用（全仓 `grep` 只有 `e.scancode`，没有 `e.key`）；
  3. 结论只能落在 `down()` 的轮询兜底上 —— **用户的现象本身就是证据**：若索引是 scancode，按回车不可能让 `[13]` 为真。
- 修法：`down()` \*\*只读 \*\*`held`（纯事件驱动）；再补 `WINDOWFOCUSGAINED` 也清空 `held`（失焦期间可能漏 KEYUP）。
- 断言（`_verify_act1_keys.py` 15 → 22 项）：\*\*伪造一个「回车时 `[13]` 为真」的 \*\*`get_pressed`，
断言 `down(SC_J)` 仍为 False；端到端「站在必涂格上按回车 1 秒 → 格子不变」；「按 J 仍然要能涂」；失焦/回焦点都清空。
- 真窗口端到端复核：连按回车 2 秒，`progress 0 → 0`、脚下仍是白格、`down(J)=False`。
- 合计 **19 个脚本 485 项全绿**。HANDOFF §5 新增第 14 条坑。
